# EXP-034 SUMMARY：judge 被骗的速度由能力差距决定，还是由 judge 本身决定（Finding）

## 1. 结论

- **judge 大小的效应很大，在所有算法下都成立。** 7B judge 让 hack 起点推迟约 3–4.5 倍。
- **策略大小的效应只在 7B judge 下出现。** 1.5B judge 下，两个策略都在第 18–22 步被骗。7B judge 下，1.5B 策略比 0.5B 策略早。
- **预登记的判决是"依赖坐标"。** 按步数判 H_judge，按 KL 判"两者都有贡献"。按 SPEC 7.2，结论降为描述。
- 每格只有 2 个种子。阶段 2 因 S4 没有跑，区间很粗。

## 2. 设置

- **策略。** P05 = sft-s2（Qwen2.5-0.5B 做过 SFT）。P15 = 用同一配方训练的 Qwen2.5-1.5B。第 0 步贪心正确率：P15 0.61，P05 0.33。
- **judge。** J15 = Qwen2.5-1.5B-Instruct，J7 = Qwen2.5-7B-Instruct。judge 不看参考答案。奖励是校准后的判决概率 G_cal。
- **训练。** GSM8K。GRPO，lr 3e-6，每步 8 题 × 8 条，150 步，β = 0，组内 std 归一化。每格种子 301、302。
- **主端点 t½。** 在 5 步训练窗口里，h = (FPR − FPR0)/(1 − FPR0) ≥ 0.5，并且下一个窗口也满足。
  - FPR 是 judge 在金标准错答上判"对"的比例。
  - FPR0 是第 0 步样本 d8 上的值。

静态闸门 [`results/static_J15.json`、`static_J7.json`]：

| judge | 策略 | d8 AUC(G) | FPR0 |
|---|---|---|---|
| J15 | P05 | 0.744 | 0.448 |
| J15 | P15 | 0.678 | 0.555 |
| J7 | P05 | 0.889 | 0.158 |
| J7 | P15 | 0.873 | 0.218 |

四格都过闸门（AUC ≥ 0.60）。

### 3.2 步数坐标的 AFT 分析（预登记）

AFT 是带删失的对数正态加速失效模型。来源：`analysis_stage1.json` → `aft`。

| 量 | 估计 | 95% 区间 |
|---|---|---|
| Δ_J（judge 1.5B → 7B，ln 步数） | 1.50 | [1.18, 2.12] |
| Δ_P（策略 0.5B → 1.5B） | −0.13 | [−0.76, 0.18] |
| C_gap = Δ_P + 0.717·Δ_J | 0.94 | [0.69, 1.16] |
| 交互项 | −0.42 | [−1.66, 0.20] |

- 前提 P1 满足（Δ_J > 0）。
- Δ_P 区间含 0，C_gap 区间下界 > 0。按规则判 **H_judge**。
- 纯差距假设被排除。它要求 Δ_P ≈ −1.07，但区间上界只到 0.18。

### 3.3 KL 坐标（敏感性分析）

来源：`aft_kl`。

| 量 | 估计 | 95% 区间 |
|---|---|---|
| Δ_J | 0.91 | [0.79, 1.28] |
| Δ_P | −0.32 | [−0.69, −0.20] |
| C_gap | 0.33 | [0.18, 0.43] |
| r（0 = 纯 judge，1 = 纯差距） | 0.49 | [0.32, 0.79] |

- 按 KL 判"两者都有贡献"。这和步数坐标的判决不同，所以判"依赖坐标"。
- 原因：在 7B judge 下，1.5B 策略被骗时的 KL 更小（0.19–0.21，0.5B 策略是 0.30）。
- KL 区间的 bootstrap 是看到步数结果之后加的。

### 3.4 事后检查：格式丢失（不在 SPEC 内）

来源：`results/posthoc_lenient*.json`。

- 一些策略后期不再写 "#### n"。严格金标准把"答对但没有格式"算成错答。这时 judge 说"对"并不算被骗。
- 改用宽松金标准（没有 "####" 时取最后一个数）重算 t½：
  - P05×J7-s302：68 → 删失。它的"错答"里有 27% 其实答对了。
  - P15×J7-s301：64 → 88。它的"错答"里有 48% 其实答对了。
  - 其他 run 不变，或只差 0–2 步。
- 宽松算法下，P05×J7 的两个种子都删失。涉及这一格的对比不可识别（SPEC 补充 1.4）。
- 能说的话：
  - 1.5B judge 下，策略大小没有影响（18–22 步）。
  - 7B judge 下，1.5B 策略在第 88–90 步被骗，0.5B 策略 150 步内都没有被骗。

### 3.5 hack 的形式（描述）

- 1.5B judge：回答从约 95 token 变长到 190–220 token，错答误判率到 0.99–1.00。
- 7B judge：回答变长到 143–159 token，评测集误判率只到 0.40–0.80。其中三个 run 丢掉答案格式（格式率 0–0.09）。
- 没有出现重复答案行或短回答。

## 5. 读法

- **最稳的发现：** 在这个范围内，judge 从 1.5B 换到 7B，比策略从 0.5B 换到 1.5B，对 hack 速度的影响大得多。这和 Gao 等（2210.10760 §3.4，合成 RM）的方向一致。
- **新的地方：** 策略效应不是 0，而是取决于 judge。
  - judge 弱时，0.5B 策略约 20 步就能骗过它，可能已到地板，更大的策略也快不了。
  - judge 强时，更大的策略更早找到骗法。
  - 这是一个交互。2 个种子下，交互项的区间含 0。
- **候选说法：** 被骗速度主要由 judge 决定；judge 足够强时，策略能力才开始起作用。检验它需要更多种子和第三个尺寸点。

## 6. 局限

- 每格 2 个种子。percentile bootstrap 每格只有 3 种不同的重抽，所以区间偏窄。
- 只有两个尺寸点、一个模型家族（Qwen2.5）、一个任务、一个 prompt。
- 2×2 只能估计两个斜率之比。
- 宽松金标准分析和 KL 区间都是事后加的。
- 实现和 EXP-023 不同：所有格用 micro-batch 2 和 fused AdamW，在 gpu-server-2 上跑。两者在数学上等价。P05×J15 的 t½（18–21 步）和 EXP-023 的量级一致。
- **新颖性：** 最接近的工作是 2210.10760（合成 RM 的 2×2），2603.12246 和 2608.17776（只变 judge），2204.05862（行加对角线，训练的 PM）。它们都没有在冻结 LLM judge 上用交叉格点测起点。

## 7. 下一步

- 每格加到 4–6 个种子，先确认交互项。约 12–18 A100 小时。
- 在 7B judge 下加 3B 策略，看强 judge 时的策略效应会不会继续变大。
- 改用宽松金标准，或给奖励加格式分，去掉格式丢失这个混杂。
