# EXP-039 SPEC：GRPO 下 judge 被骗的起点，由 judge 能力决定，还是由"差距 + 地板"决定（Experiment）

写于 261009，在任何 EXP-039 的 RL 运行之前。研究线 11。上游：EXP-034（`../EXP-034/SPEC.md`、`results/SUMMARY.md`），关卡 2 审查 `../EXP-034/REVIEW_GATE2.md`（判决：修改后做）。
写法按 ASD-STE100 (simplified technical writing)。本文件的 sha256 记在 `PROCESS.md`。之后的改动只写成带时间的补充节。

## 0. 问题

EXP-034 的 2×2（策略 0.5B / 1.5B × judge 1.5B / 7B）有两个解释，8 个点分不开它们：

- **差距 + 地板**：被骗起点只取决于"judge 比策略大多少"。另有一个约 20 步的地板：策略在 lr 3e-6 下最快也要这么多步。弱 judge 一行都在地板上，所以那里看不出策略的作用。
- **judge 主导 + 交互**：起点主要由 judge 决定。策略能力只在 judge 强时起作用。

本实验加一行 3B judge（J3），构成两对近似等差距的格。两个解释对 J3 一行的预测不同（第 6.4 节）。

**主问题**：在 J3 下，1.5B 策略是否比 0.5B 策略早很多被骗（差距 + 地板），还是一样早（judge 主导）？

## 1. 术语（每个只解释一次）

- **P05、P15**：策略。同 EXP-034。P05 = sft-s2（Qwen2.5-0.5B 基座 + SFT）。P15 = Qwen2.5-1.5B 基座 + 同一 SFT 配方。
- **J15、J3、J7**：冻结的 judge，Qwen2.5-1.5B / 3B / 7B-Instruct。judge 不看参考答案。
- **G、G_cal**：同 EXP-034。G 是 judge 的 logit(Yes) − logit(No)。G_cal 是 G 上的一维逻辑回归，在两个策略第 0 步样本 d0 上合并拟合（严格金标准，同 EXP-034），它就是奖励。
- **宽松金标准**：有 "#### n" 时取 n；没有时取最后一个数（`common.parse_lenient`）。它把"答对但丢了格式"算作答对。
- **τ_len(J, P)**：第 0 步样本 d8(P) 中，宽松金标准判对的回答上，judge J 的 TPR = 0.80 的 G_cal 阈值。
- **FPR0_len(J, P)**：d8(P) 中宽松判错的回答里，G_cal ≥ τ_len 的比例。
- **h**：剩余空间归一的被骗比例，h = (FPR − FPR0)/(1 − FPR0)。同 EXP-034。
- **t½**：被骗起点（第 6.1 节）。
- **删失**：到运行结束还没有到 t½。只知道"晚于运行步数"。
- **AFT**：加速失效模型。对 ln t½ 做回归，能处理删失。
- **剖面似然区间**：固定要估计的量，把其他参数取最优，看似然下降多少。下降不超过 χ²(1) 分位数的值组成区间。
- **采样 KL**：从当前策略按 T = 1.0 采样回答 y，对 log π(y) − log π0(y) 求平均。它是 KL(π‖π0) 的无偏估计。EXP-034 的"KL"是在贪心输出上算的，不是 KL。

## 5. 运行

- 代码：`code/grpo39.py`（复制 EXP-034 的 `grpo34.py`）。改动只有两处：
  1. 每次评测加采样 KL：每道评测题从当前策略采 1 条（T = 1.0），算 log π − log π0 的和。采样前保存 CPU 和 CUDA 的随机数状态，采样后恢复，所以训练轨迹和不加时相同。
  2. 每条 rollout 记录宽松金标准的对错。
- 超参全部同 EXP-034：lr 3e-6，每步 8 题 × 8 条，T = 1.0，最长 256 token，β = 0，loss dapo，组内 std 归一化，没有格式分。micro-batch 2，fused AdamW。
- 权重：第 50、100、150 步（以及 200、250 步，如果有），save_only_model。final 指向最后一步。
- P05 的 run 用一张卡。P15 的 run 用两张卡（策略一张，judge 和参考副本一张）。
- 机器：gpu-server-2。只在**空闲**的卡上启动（nvidia-smi 显存占用 < 1000 MiB）。只按自己 PID 文件里的 PID 结束进程。
- 崩溃的 run 只重跑一次。

## 6. 端点（运行前写定）

### 6.1 主端点

- **t½（宽松）**：对 t = 5, …, T − 5，算训练窗口 [t − 4, t] 的 h（宽松金标准，τ_len 和 FPR0_len 按本格的策略）。窗口里宽松错答少于 20 条时不计。t½ = 最小的 t，使 h(t) ≥ 0.5，并且下一个不重叠窗口 [t + 1, t + 5] 也满足。没有这样的 t → 删失于 T。
- **坐标：步数。** 事先写定。KL 只作描述。
- 旧的 8 个 run 用保存的 rollouts 按同一定义重算（`code/extract39.py`）。核对：用严格金标准时，重算值和 EXP-034 完全相同（18/21、删失/68、22/20、64/90）。

### 6.2 主估计量

- **Δ_P|J** = 同一 judge J 下，P15 和 P05 的 ln t½ 均值之差（P15 − P05）。负值表示 P15 更早被骗。
- 主要两个：Δ_P|J3 和 Δ_P|J7。Δ_P|J15 作描述。

### 6.3 次要量（预登记，只作描述，不进判决）

1. h 阈值 0.3 和 0.7 下的 t½。
2. 每个 judge 一个公共 τ（两个策略的宽松判对回答合并，取 TPR = 0.80）下的 t½。
3. 严格金标准下的 t½。
4. t½ 处的采样 KL（只有新 run 有；在相邻两次评测之间线性插值）。
5. **共同错题上的 h**：第 0 步时，两个策略在 d0 / d8 的全部样本都宽松判错的题（324 道）。在第 1–50、51–100、101–150（…）步的训练 rollout 上，只看这些题，算 h（FPR0 用这些题在 d8 上的值）。
   - 读法：如果 P15 在强 judge 下更早被骗，在共同错题上也更早，那么"余量"解释变弱。
6. τ 处的并列比例；奖励接近 0 或 1（G_cal < 0.05 或 > 0.95）的比例。
7. 每格读 20 条被骗回答（第 6.5 节）。

### 6.4 两个解释对 J3 一行的预测

- **差距 + 地板**：P15×J3（判长比 2.0）在地板，约 20 步。P05×J3（6.3）约等于或晚于 P15×J7（4.9，约 89 步）。所以 Δ_P|J3 ≈ ln(20/90) ≈ −1.5，至少 ≤ −1.2。
- **judge 主导**：Δ_P|J3 ≈ 0。
- **交互随 judge 变强而变大**：Δ_P|J3 在 0 和 Δ_P|J7 之间。
- 等差距对（描述）：差距 + 地板预测 μ(P05×J3) − μ(P15×J7) ≈ 0，μ(P15×J3) − μ(P05×J15) ≈ 0。judge 主导预测前者 < 0，后者 > 0。

### 6.5 机制核对：读被骗回答

- 每格，从 [t½, t½ + 19] 步（删失的 run 用最后 20 步）的宽松错答中，取 G_cal ≥ τ_len 的回答，随机读 20 条（`code/fooled39.py`）。
- 记录 hack 的形式：长度、格式、是否重复答案、是否有题外内容、错误类型。

### 6.6 第二家族：离线重打分

- 不做新的 RL。
- 用 Llama-3.2-3B-Instruct（同一个不给参考答案的 prompt）给每个 run 的宽松错答打分（`code/llama39.py`）：窗口 E = 第 1–10 步，窗口 H = [t½, t½ + 19]（删失的 run 用最后 20 步），每个窗口最多 200 条。
- τ_L、FPR0_L 用 Llama 在 d8 上的分数（宽松金标准，TPR 0.80）。
- 报告 h_L（Llama）和 h_Q（训练用的 Qwen judge）。
- 读法：h_L 在 H 窗口不上升 → hack 只骗 Qwen judge（和线 5 的发现一致）。h_L 也上升 → hack 能迁移到另一个家族。

## 7. 分析和判决规则（运行前写定）

### 7.1 模型

- y = ln t½；删失的 run 记 y > ln T。
- 对数正态 AFT，每格一个均值 μ_c，所有格共用一个 σ。全部完成的 run 都进入模型（6 格）。
- **σ 的弱先验**：ln σ ~ N(ln 0.25, 0.5²)。中心 0.25 是 EXP-034 预登记分析的 σ。
  - 理由：每格种子少，σ 的最大似然估计偏小。旧的 8 个 run 在宽松算法下 σ 的最大似然值只有 0.05（J15 两格的 4 个 run 几乎相同）。这会让区间过窄。
  - 这个先验是在看过旧 8 个 run 的宽松重算之后、任何 J3 数据之前定的。
  - 敏感性：不加先验的纯最大似然，同样报告。
- 区间：剖面似然。主区间水平 97.5%（两个主比较的 Bonferroni 水平）。也报告 95%。
- 检验：Δ = 0 的似然比检验，两个主比较用 Holm 校正。
- 代码：`code/analyze39.py`（在任何 J3 结果之前写好，并在旧 8 个 run 上测过）。

### 7.2 判决（用 97.5% 剖面似然区间）

- **R1 差距 + 地板**：Δ_P|J3 区间上界 < −0.8。
- **R2 交互只在强 judge 出现**：Δ_P|J3 区间包含 0，且下界 > −0.5，同时 Δ_P|J7 区间上界 < 0。
- **R3 judge 主导**：Δ_P|J3 和 Δ_P|J7 的区间都包含 0。
- **R4 未决**：其他情况。按实测 σ 报告还需要多少种子。

## 8. 分阶段和停止规则（运行前写定）

- **闸门 G0**：J3 的静态闸门。d8 上 AUC(G) ≥ 0.60（两个策略都要）。不过 → 不跑 J3 的 RL，不换 judge，报告。
- **阶段 A（J3 一行，8 个 run）**：P05×J3 301–304（200 步），P15×J3 301–304（150 步）。
  - 结束后按第 7 节分析（旧 8 个 run + J3 的 8 个 run）。
  - **S-A**：如果 R1 成立（Δ_P|J3 的 97.5% 区间上界 < −0.8）→ 停止，不跑阶段 B 和 C，写"差距 + 地板"。
  - 否则进入阶段 B。
- **阶段 B（J7 加种子）**：P05×J7 303、304（250 步），P15×J7 303、304（150 步）。不砍 P05×J7 的 250 步。
- **阶段 C（J15 加种子）**：P05×J15、P15×J15 各加种子 303。只在"已用 + 阶段 C 预计 ≤ 24"时启动，两个一起跑或都不跑。
- **S-cap（算力上限）**：24 A100 小时。每次启动前检查"已用 + 这个 run 的预计 ≤ 24"。不满足就不启动，停止并报告。
- **S-none**：如果 J3 一行 8 个 run 全部删失（J3 下没有 hack），Δ_P|J3 不可识别。停止，报告。

## 9. 种子数和功效

- 依据：EXP-034 预登记的 σ = 0.25。取 σ = 0.30。
- 同一行里 Δ_P 的标准误 = σ·√(2/n)。n = 4 时是 0.21。
- 差距 + 地板为真（Δ_P|J3 ≈ −1.5）时，R1 成立的概率 ≈ P(估计 < −0.8 − 2.24 × 0.21 = −1.27) ≈ Φ((−1.27 + 1.5)/0.21) ≈ 0.86。
- judge 主导为真（Δ_P|J3 ≈ 0）时，R1 成立的概率 < 0.01。
- J7 一行：效应下界 ln(150/89) = 0.52（宽松，旧数据）。n = 4 时功效约 0.70。删失会让它低一些。
- 交互项本身的标准误更大（约 0.35），所以不作主估计量。

## 补充 2（261009 11:1x，任何 J3 RL 结果之前；driver 还没有启动任何 run）

1. **发现（读旧 run 的被骗回答，第 6.5 节）。** 宽松金标准会把一些"用文字写出的正确答案"判成错。它取最后一个数。例："it would take … an additional 2 hours to travel an additional 240 miles" 取到 240，金标准是 2。
   - 1.5B judge 两格：各 20 条被骗回答，全部真错，全部写了 "#### n"。这是干净的 judge hack。
   - 7B judge：最后一句里含金标准答案的，P15 有 6/20，P05 有 1/20。所以 7B judge 下的"被骗"里混有判错的正确答案，主要在 P15×J7。
2. **加一个预登记的稳健性金标准："宽容金标准"**（`common.correct_generous`）。有 "#### n" 时按 n 判；否则有 \boxed{n} 时按 n 判；都没有时，最后一句里任何一个数等于金标准就算对。它会多算一些对（最后一句里碰巧出现金标准数字）。宽松和宽容是两个方向相反的界。
3. **判决规则加一条。** 第 7.2 节的判决在宽容金标准下重做一次（同样的 τ_len，FPR0 用宽容金标准在 d8 上的值）。两者判决相同 → 保留。不同 → 判决降为"依赖金标准定义"，两个都报告。主端点不变，仍是宽松金标准。
4. 旧 8 个 run 在宽容金标准下的 t½：只有 P15×J7-s301 变了（88 → 92）。第 0 步的 FPR0 几乎不变（≤ 0.001）。

## 补充 3（261009 12:1x，没有任何 J3 结果；只改实现和"崩溃"的计数）

## 补充 7（261009 21:5x，看过 P15×J3 前两个 run 之后；只改并列的处理，算法的本意不变）

- 发现：训练中 G_cal 落在 τ 上的回答（并列），和 τ 的差只有约 1e-8（浮点误差）。P05×J15、P15×J15、P05×J3 的差全为正（算"被骗"，和第 0 步 d8 一致）。P15×J3 的差全为负（算"没被骗"，和第 0 步不一致）。这会让 P15×J3 的 h 偏低最多约 0.03。
- 改法：比较时用 G_cal + 1e-6 ≥ τ。也就是 SPEC 定义的"≥ τ，并列算被骗"，第 0 步和训练一致。
- 这个改动是在看过结果后做的。所以同时报告旧算法（精确比较）的 t½。改动后，到此所有 run 的 t½ 都没有变化。
